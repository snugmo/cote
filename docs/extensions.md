# Extensions Reference

> **On-demand reference** — read when working on an extension image under `extensions/`. Extensions build on top of the base image to add specific capabilities without polluting the base. Each extension has its own `Containerfile`, `build.sh`, and `README.md`. Extensions keep the base lean while enabling agent-ready workspaces when needed.

**To use an extension, replace the `tools` container image in your Devfile with the extension image reference.**

## Available extensions

- **Hermes Agent** (`extensions/hermes/`) — Installs [Hermes Agent](https://hermes-agent.nousresearch.com/) with ACP (Agent Communication Protocol) support for IDE integration. Uses a shallow git clone of the upstream repo (pip installs are unsupported). Works with VS Code (ACP Client extension), Zed (ACP Registry), and JetBrains (ACP plugins).
- **Pi Coding Agent** (`extensions/pi/`) — Installs the [Pi coding agent](https://pi.dev) ([earendil-works/pi](https://github.com/earendil-works/pi)) from the official npm package (`@earendil-works/pi-coding-agent`) with `--ignore-scripts`. Terminal coding agent with interactive TUI, print, RPC, and SDK modes. Bakes in the keyless `example` provider (`https://llm.example.com/v1`, model `qwen3.8-27b`) as the default LLM in `~/.pi/agent/models.json` + `settings.json`. Its build pulls the base image `${REGISTRY}/cote:<same git-describe tag>-base` from the registry (override with `DEV_BASE_IMAGE`), so the base image must be pushed before building pi; publish with `./extensions/pi/build.sh push`.
- **PiG (Pi in Go)** (`extensions/pi-in-go/`) — Installs [PiG](https://pi-in-go.dev/) ([MichaelKinsy/PiG](https://github.com/MichaelKinsy/PiG)), a faithful Go implementation of the Pi coding agent, from the official npm package (`@pi-in-go/pig`) with `--ignore-scripts`. A single native binary (no Node runtime needed unless running TypeScript extensions) with interactive TUI, print/JSON, RPC, and Go SDK modes; extensions in Go, Rust, Python, or Node, plus Piglets. Bakes in the keyless `example` provider (`https://llm.example.com/v1`, model `qwen3.8-27b`) as the default LLM in `~/.pig/agent/models.json` + `settings.json`. Its build pulls the base image `${REGISTRY}/cote:<same git-describe tag>-base` from the registry (override with `DEV_BASE_IMAGE`), so the base image must be pushed before building PiG; publish with `./extensions/pi-in-go/build.sh push`.
- **Xpra Remote X11 Desktop** (`extensions/xpra/`) — Installs the [Xpra](https://xpra.org) server (Fedora package, with its headless Xorg/Xdummy + xauth deps) plus X11 desktop support (`xorg-x11-server-Xvfb`, `xset`, `xinput`, `xorg-x11-fonts-Type1`, `openbox`, `xterm`, `kitty`) and the [xpra-html5](https://github.com/Xpra-org/xpra-html5) browser client, installed from the upstream git repo at a pinned commit into `/usr/share/xpra/www` (not on PyPI). The `xpra-desktop` launcher starts a daemonized `start-desktop` session (Xdummy by default, `--xvfb` for Xvfb) running openbox and xterm, served on a TCP/WebSocket port with the HTML5 client — a headless container desktop usable from any browser or a native `xpra` client. The image's `CMD` is the `xpra-entrypoint` script: with no arguments it serves an empty X11 desktop (openbox) on a TCP/WebSocket port for the container's lifetime, and with arguments it runs the command as the container's foreground process inside a daemonized session (its stdout/stderr go to the container logs and its exit code becomes the container's). Its build pulls the base image `${REGISTRY}/cote:<same git-describe tag>-base` from the registry (override with `DEV_BASE_IMAGE`), so the base image must be pushed before building; publish with `./extensions/xpra/build.sh push`.

## Build & publish

The `Publish` workflow (`.github/workflows/publish.yaml`) is the canonical publish path — it builds the base image and all four extensions for `linux/amd64` + `linux/arm64` and pushes multi-arch manifests to quay.io (see AGENTS.md → *CI Publishing*). The per-extension `build.sh` scripts are for **local builds only** (buildah, tag from `git describe`, registry override). Because an extension build pulls the base image `${REGISTRY}/cote:<same tag>-base` from the registry (override with `DEV_BASE_IMAGE`), **the base image must be pushed first**. Publish a single extension locally with `./extensions/<name>/build.sh push`.

## Credentials / gotchas

- **Hermes credentials**: Hermes agent requires API credentials configured before first use. Run `hermes model` inside the workspace or pre-populate `~/.hermes/.env` via a ConfigMap/Secret.
- **Pi credentials**: The baked-in `example` provider (`qwen3.8-27b`) needs no API key, so `pi` works out of the box. For any other provider, pre-populate an env var (e.g. `ANTHROPIC_API_KEY`) via a ConfigMap/Secret, or run `pi` and use `/login`. Set `PI_OFFLINE=1` to silence startup network calls (update check, telemetry) in air-gapped workspaces.
- **PiG credentials**: The baked-in `example` provider (`qwen3.8-27b`) needs no API key, so `pig` works out of the box. For any other provider, pre-populate an env var (e.g. `ANTHROPIC_API_KEY`) via a ConfigMap/Secret, or run `pig` and use `/login`. Set `PIG_OFFLINE=1` (or `PI_OFFLINE=1`) to silence startup network calls (update check, model-catalog fetch) in air-gapped workspaces.
